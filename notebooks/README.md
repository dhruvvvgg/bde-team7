## How it was tested, and what was not tested

**It was tested in the project sandbox with `jupyter nbconvert --to notebook --execute`, not in real
Google Colab.** The test setup was:

- a fresh Python 3.11.15 virtual environment containing only nbconvert and ipykernel;
- an empty working directory, so the notebook cloned the repository from GitHub over HTTPS and
  installed the pinned `requirements.txt` itself.

Results:

- **Default settings** (`RUN_CHIRPS_DOWNLOAD = False`, `RUN_PYSPARK = False`): 0 errors in
  4 min 36 s. All 62 tests passed inside the fresh clone. Comparing the regenerated outputs with the
  committed ones with `scripts/verify_reproduction.py` found 0 differences across 18 files.
- **With `RUN_PYSPARK=1`**, using Java from the sandbox and pyspark 3.5.3 from PyPI: 0 errors in
  4 min 30 s. Spark read 253,828 rows from 19 partitions, and its rows per state, mean depth by
  season and stress counts matched pandas exactly. This run is the saved executed copy.
- **`RUN_CHIRPS_DOWNLOAD = True` was not tested in the notebook.** The download scripts themselves
  were run earlier in this project, outside the notebook.

## What may behave differently in real Colab

- **Paths.** Colab starts in `/content`, so the notebook clones to `/content/bde-team7` and changes
  into it. If you rerun the first cells after a runtime reset, the existing clone is reused; delete
  it to get a fresh copy.
- **Package versions.** Colab's preinstalled packages (numpy, pandas, pyarrow, scipy, matplotlib)
  differ from the pinned versions. `pip install -r requirements.txt` replaces them, which may print
  dependency-resolver warnings for packages this pipeline does not use. If imports then behave
  oddly, use Runtime → Restart session and run the cells again.
- **Runtime resets.** Colab runtimes are temporary. Everything the notebook writes (outputs,
  reports) is lost when the runtime resets, unless you copy it to Drive. Nothing is pushed back to
  GitHub.
- **Memory.** The largest step holds the 253,828 × 84 table plus intermediate frames in memory. Measured
  peak memory in the sandbox: 1.07 GB (features), 1.47 GB (extension features) and 1.75 GB (figures).
  All are well within a standard Colab runtime (about 12 GB). The PySpark
  section starts a local JVM, which adds about 1 GB.
- **Java and PySpark.** Colab usually has Java, but if `spark` fails to start, install it with
  `!apt-get install -y openjdk-17-jre-headless`. The pinned pyspark 3.5.3 needs Java 8, 11 or 17.
- **Private repository.** If the repo is private, the clone needs a token in `REPO_URL` (see the
  settings cell). Never save the notebook with a token in it.
- **CHIRPS download.** If you turn it on, it streams about 13 GB from `data.chc.ucsb.edu` and takes
  more than an hour. Colab's network and runtime limits may interrupt it, but the download is
  resumable: rerun the cell to continue.

## Error-metric notebooks (before vs after preprocessing)

- **`error_metrics_before.ipynb`**: the raw CGWB table, before any quality control.
- **`error_metrics_after.ipynb`**: the cleaned 2,759-well table the pipeline uses, followed by a before/after comparison.

Both compute RMSE, MSE, MAE, MAPE, R², NRMSE, MedAE and Bias (mean error), plus sMAPE, for three fixed past-only forecasting
rules scored on the 2018–2022 readings, with tables and graphs (by rule, season, year and state). The committed files already
contain their outputs. Metric code is in `src/gwstress/error_metrics.py` (tested in `tests/test_error_metrics.py`); the
notebooks are generated by `scripts/16_make_error_notebooks.py`. Results are also saved to `reports/tables/error_metrics_*.csv`.

To re-run (the "before" notebook first, because "after" cross-checks against the CSV that "before" saves):

```bash
pip install nbconvert ipykernel      # plus the packages in requirements.txt
jupyter nbconvert --to notebook --execute --inplace notebooks/error_metrics_before.ipynb
jupyter nbconvert --to notebook --execute --inplace notebooks/error_metrics_after.ipynb
```

Tested with nbconvert in a clean Python 3.11 environment, not in Google Colab. Each notebook takes under 30 seconds.
