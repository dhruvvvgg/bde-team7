# Decisions log (retrain on the Spark table)

Conservative choices made without asking, in the order they came up.

1. **Branch.** `retrain-on-spark` was created from `review2-modeling` (`9270ea6`). The five Spark files (`src/gwstress/spark_pipeline.py`,
   `scripts/run_spark.py`, `scripts/verify_spark_parity.py`, `tests/test_spark_pipeline.py`, `requirements-spark.txt`) were copied
   byte-for-byte from `spark-first-preprocessing` (`d343814`); no merge was needed because those branches differ from their common base
   (`fd8f9c2`) only by new files. `main`, `review2-modeling` and `spark-first-preprocessing` were not pushed to.
2. **Environment.** Python 3.11.18, OpenJDK 21, torch 2.15.0 (CPU use; the PyPI wheel is the CUDA build, no GPU present), xgboost 3.2.0,
   scikit-learn 1.9.1, pyspark 3.5.3, and the pinned reference stack from `requirements.txt` (numpy 2.4.6, pandas 3.0.6, pyarrow 25.0.1,
   scipy 1.17.1). The first install attempt pulled pandas 3.1.0 / pyarrow 26.0.0; the pins were then restored and the parity check was rerun
   (identical result). 4 CPU cores, 15 GB RAM.
3. **Paths.** `modeling/paths.py` reads `BDE_PROCESSED` and `BDE_RESULTS` (defaults: `processed/`, `results/`, so the old path still works).
   No model, grid, seed, split, metric, mask or threshold was edited.
4. **Test command.** `python -m pytest -q tests`, not bare `pytest`: on this branch bare `pytest` also collects `modeling/gap_test.py` (a
   script that happens to match pytest's `*_test.py` pattern and needs `results/` to exist).
5. **Driver.** `modeling/run_retrain.py` runs the same steps, scripts and arguments as `run_pipeline.py --mode full` but skips jobs whose
   output is already complete (resumable) and runs single-thread jobs 4 at a time (`run_pipeline.py` used 3 and 6). Thread count only changes
   floating-point summation order.
6. **Not committed.** `processed/spark/` (58 MB, regenerated by `scripts/run_spark.py`) and all `results_spark/**/*.npy` prediction files
   are git-ignored. Everything else (JSON, CSV tables, logs of the checks) is committed.
7. **Extra control run (not requested).** Because several validation-selected hyperparameters changed between the old results and the new
   run (see COMPARISON.md section 0 and the note on seed noise), the same code was also run on the **pandas table** in this same
   environment, into `results_control/`. This separates "the data changed" from "a fresh run on this machine differs from the old
   run", and is used only to interpret the differences. `results/` was never touched.
8. **Seed-noise band.** A change is called "within noise" when |new - old| <= 2 x the pooled per-seed standard deviation of the two runs
   (3 seeds each). Single-seed cells (unseen-state results) and deterministic rules have no sd; fixed bands are used (0.02 m for MAE/RMSE and 0.01
   otherwise in the unseen-state table; 0.01 / 0.005 for deterministic rules). Per-seed sd does not capture the variation caused by
   different validation-selected configurations, which is why the control run was added.
9. **Git identity.** Commits use the identity configured in this environment; the messages carry no attribution lines and no session links.
